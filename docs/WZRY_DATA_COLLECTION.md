# 王者荣耀数据采集方案调研

**调研日期**: 2026-02-02
**调研人**: Pi (AI Assistant)

## 项目目标

1. 王者荣耀每日复盘
2. 公平度判断（匹配机制分析）
3. 李白出装建议

## 数据采集难点

- 王者荣耀没有公开 API
- 移动端游戏，无法直接抓包
- 官方对数据获取有严格限制

## 方案对比

### 方案一：第三方平台/网站爬取

**可用平台**:
- 王者营地 App（官方）
- 掌上王者 App
- 第三方战绩查询网站

**技术栈**:
- Python + requests/selenium
- 模拟登录获取战绩 API

**优点**:
- 数据相对完整（KDA、装备、MVP等）
- 不需要视觉识别

**缺点**:
- 依赖第三方平台稳定性
- 可能触发反爬机制
- 数据延迟（非实时）

**参考**: CSDN 有多篇文章讲解爬取王者荣耀数据
- herolist.json 英雄列表 API
- Python 采集最低战力信息

---

### 方案二：视觉识别（OCR + CV）

**流程**:
1. 手机录像/截图游戏界面
2. 传输到 PC（投屏/无线传输）
3. 使用 OCR 识别文字（分数、装备名等）
4. 使用 CV 识别图像（英雄头像、技能等）

**技术栈**:
- PaddleOCR / Tesseract（文字识别）
- OpenCV（图像处理）
- YOLO / CNN（英雄/物品识别）

**优点**:
- 完全自主控制
- 可获取实时数据
- 不依赖第三方

**缺点**:
- 需要大量训练数据
- 识别准确率需要调优
- 开发周期较长

**参考项目**:
- FGO-py：PP-ONNXCR 游戏界面文字识别
- OCR-GALGAME-SystemTray：基于 OpenCV+Tesseract
- 腾讯 WeTest：游戏场景 CV 识别方案

---

### 方案三：投屏 + 实时分析

**流程**:
1. 手机投屏到 PC（scrcpy / ADB）
2. PC 端实时捕获画面
3. 分帧处理 + OCR/CV 识别
4. 实时生成数据

**技术栈**:
- scrcpy（开源投屏工具）
- Python + OpenCV 实时处理
- 结合 OCR 识别

**优点**:
- 实时性最好
- 可用于直播/实时复盘

**缺点**:
- 需要投屏环境
- CPU 占用较高
- 复杂场景识别难度大

---

## 推荐实施路径

### 阶段一：战绩数据（简单）
**目标**: 获取历史战绩、KDA、胜率等
**方法**: 爬取王者营地 API 或第三方网站
**产出**: 历史数据 CSV/JSON

### 阶段二：局内数据 OCR（中等）
**目标**: 识别结算界面的数据
**方法**: 截图 + PaddleOCR
**产出**: 自动化数据提取脚本

### 阶段三：实时视觉分析（困难）
**目标**: 实时分析对局、出装建议
**方法**: 投屏 + CV + 模型推理
**产出**: 实时复盘/辅助工具
